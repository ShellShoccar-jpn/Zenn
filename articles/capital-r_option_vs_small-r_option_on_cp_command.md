# Hacker NewsでUNIXユーザーにとっての味わい深いスレッドがあった

先月末（2026-09-30）、Hacker News（HN）で、[cp: -r or -R?](https://movq.de/blog/postings/2026-09-30/0/POSTING-en.html)という記事を[紹介するスレッド](https://news.ycombinator.com/item?id=49910465)が立ち上がり、100を超えるコメントが集まっていた。

この議論が面白かったので、私も調べてみた。

# 今でこそ同じ意味を持つ`-r`と`-R`

cpコマンドに限らず、主なUNIXコマンドで「指定ディレクトリー以下を再帰的に」という意味を持たせるオプションとして、`-r`や`-R`が用意されている。そして、どちらを指定しても同じという場合が多い。なので、

> 「指定ディレクトリー以下を再帰的に」という時に使うのって、`-r`だっけ？`-R`だっけ？どっちが正しいんだっけ？

と思う人も多いだろう。2026年の今においてその答えは「どっちも正しい」であるが、昔は実は違っていた。

# `-r`と`-R`の歴史

というわけで、自分なりに調べてみたのでまとめる。

## 〜1983年：`-r`や`-R`の登場前

「指定ディレクトリーの中を再帰的に」などという、そんな便利なオプションが無かった頃は、findと[cpio](https://ja.wikipedia.org/wiki/Cpio)を組み合わせたイディオム（ワンライナー）でコピーするという技法が紹介されていた。

cpioというのは、みんな大好きtarコマンドのようなアーカイバーコマンドで、実際にtarとどっちがいいかで論争になっていたこともある。

この方法でコピーした場合に注目すべき点は、特殊ファイルの扱いである。例えばシンボリックリンクファイルがあると、それを開いて読み出した中身を、同じ名前でコピー先に作成した通常ファイルに書き込むという処理になる。

HNの上記のスレッドによれば、この技法は次に記述する`-r`の登場（1983年）以降も5年くらい生き長らえていたようである。

## 1983年：`-r`の登場

1983年の4.2BSDで、cpに`-r`オプションが初登場したという。HNスレッドによれば、これはcatに`-v`オプションを実装したのと同じ人によって追加されたのだという。

なぜ、HN住人が`cat -v`の話を持ち出したのかといえば、catの`-v`オプションもまた是非をめぐって一波乱を巻き起こしたオプションだったからなのだろう。というわけで、cpの`-r`オプションもまた、その後に問題点が明らかになっていく。

なお、HN住人によれば、`-r`は登場してから普及するまでに5年以上の月日を要したという。

## 1980年代後半：`-r`の問題点が広く認識される

`-r`登場前の歴史を振り返れば理由を想像するのは難しくないだろうが、`-r`はその技法をcpの機能として取り込むようにデザインされた。つまり、既に書いたように、例えばシンボリックリンクファイルがあると、それを開いて読み出した中身を、同じ名前でコピー先に作成した通常ファイルに書き込むという動きをする。

ということは、`/dev/zero`という特殊ファイルに対してやったらどうなるだろうか？このファイルは永遠にゼロ（`0x00`）を返してくるといういわばサイズ無限大の特殊ファイルである。これを真面目に読んで別の場所にコピーしようものなら、どれだけ巨大なディスク空き領域があったとしても、そこがゼロで埋め尽くされてコピーに失敗することになる。

**`cp /dev/zero ~/dev_zero`などと実行すればその問題点を体験できるが、不毛なのでやらないことをお勧めする。**

## 1990年：`-R`の登場

4.3BSD-Renoというバージョンにおけるcpコマンドの書式を見ると、ここで`-R`オプションが登場する。なお、`-r`は載っていない。互換性のために、従来通りの動作をするオプションとして残されていたが、隠しオプションになった。

そして、`-R`はまさに`-r`の問題点を解消したオプションだった。すなわち、特殊ファイルを特殊ファイルのままコピーするものであり、シンボリックリンクもシンボリックリンクとしてコピーするものであった。

## 1992年：POSIX.2の策定

この年、シェルや標準コマンドの分野について規定した新たなPOSIX文書（POSIX.2）が策定された。cpは標準コマンドの一つであるわけだが、さて、cpコマンドのオプション`-r`や`-R`はPOSIX.2の中では何と説明されていたのだろうか。

実は両方記載されていた。`-R`は上記で説明したとおりの動作をするものであることが書かれていたのに対し、`-r`は「実装定義」（それぞれの実装者が定義する）である旨が書かれた。

そもそもPOSIX文書というものは、POSIX文書を出している組織が仕様を勝手に決めているわけではなくて、世の中のUNIX系OSを見渡して、「だいたいこうなっている」という内容をまとめたものなので、UNIX系OSで`-r`オプションを実装しているものが主流である限りは言及する。ただ、好ましくないオプションであるとして廃止される流れがあり、実際にも4.3BSD-Renoのように表向きには廃止している実装もあったことから、「実装定義」という説明になったのだと思われる。

そもそも4.3BSD-Renoは後にリリースされる4.4BSDの暫定版であり、POSIX.2仕様のモデルになることを目指して設計されたもののようである。

## 1992年：GNU coreutilsの`cp -r`はまだ、オリジナル動作

ここで、本記事で最初に紹介した記事「[cp: -r or -R?](https://movq.de/blog/postings/2026-09-30/0/POSTING-en.html)」の内容が出てくる。1992年のGNU coreutilsの最初のコミットにおける`src/cp.c`の抜粋だ。

```c:src/cp.c
case 'r':
    flag_recursive = 1;
    flag_copy_as_regular = 1;
    break;

case 'R':
    flag_recursive = 1;
    flag_copy_as_regular = 0;
    break;
```

このコードから想像できるように、この頃のGNU coreutilsのcpコマンドは、`-r`と`-R`を区別しており、`-r`はオリジナルどおりの動作をするようになっていた。

## 2001年：POSIX上で、`-r`は「obsolescent（廃止予定）」に

この年に公開されたPOSIX.1-2001では、遂に「obsolescent（廃止予定）」という扱いになった。

## 2002年：GNU coreutilsの`cp -r`は、`cp -R`化された

GNU coreutilsの最初のコミットが登場してから10年が経過したこの年、GNU coreutilsの`cp -r`はついにオリジナルの動作を捨てた。`-r`というオプションは残されたものの、意味は`-R`オプションと同一になった。こうして現在に至り、現在のユーザー達は「あれ、どっちだっけ？」と首をかしげるようになったのだ。

ちなみに、オリジナルの`cp -r`相当の動作は残されており、**どうしてもオリジナルの再帰的コピーがやりたい人は`cp -r --copy-contents`などと書けばできる**ようになっている。

## 2008年：POSIX上で、`-r`は廃止

そして、この年に公開されたPOSIX.1-2008では、予告されていたとおり`-r`が廃止された。

ただし、先程も説明したようにPOSIX文書は「だいたいこうなっている」という内容をまとめたものなので、`-r`オプションについてまったく言及されなくなったわけではなく、「もう規定されていないが一部の実装には存在しうる」というふうには記載されており、決して`-r`が無かったことにしているわけではない。

# まとめ

`-r`、`-R`というオプション一つ（二つ）とってみても、味わい深い話が出てくる。それがUNIX。
